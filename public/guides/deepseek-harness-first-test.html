DeepSeek Harness First Test: Setup Errors and Demo Limits

Quick answer: DeepSeek Harness is a preview agent interface, not a model. When I tested it, DeepSeek's own API failed with an insufficient balance error, an OpenCode route failed with "model is unavailable", and an OpenRouter key worked. The two-stroke engine HTML it built was still buggy after I asked for fixes.

I recorded this on September 1, 2026, a couple of weeks after DeepSeek announced the harness as a developer preview. The idea that grabbed me is that everything is a plugin: models, tools, skills, sessions and the file system can each be switched on or off. I wanted to see how far I could get in one sitting, from install to a finished demo.

What DeepSeek Harness is

DeepSeek's harness page describes an open-source agent harness built on an "everything is a plugin" architecture, available as a desktop app or as a web UI you start from code. The GitHub README labels it a developer preview and warns, in capitals, that there will be compatibility-breaking changes. It also asks you to read the safety notice before running it.

Take that seriously. This is a tool that can edit files and run shell commands in whatever workspace you hand it, and its plugins and APIs are still moving. Try it in a project you can restore, not your only copy of something important.

Two ways to start it

In the video I mention the one-line npx command, but what I actually ran was the from-source build: a pnpm install, a build that took longer than I expected, then the web command to serve it on localhost. The README documents both routes:

# quickest route, needs Node.js
npx @deepseek-ai/dsh web

# what I did in the video: build from source
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

According to the README, the web UI starts at http://127.0.0.1:3080 by default and opens your browser, and --no-open skips that. When it opened for me, a notice said the harness is still in testing for harness developers and that many areas need improvement. I accepted it and carried on.

Workspace, mode and plugins

I pasted my DeepSeek API key, then picked a workspace. I chose Tube Analytics, my main project. DeepSeek's quickstart notes that the session composer stays unavailable until you select a workspace, which matches what I saw.

I stayed in Standard mode, which the UI describes as a full coding agent with file editing, shell, file and web search. It listed 27 session plugins enabled by default, plus a set of global plugins you can turn off from the configuration file. There's also a Creator mode for customising plugins. I didn't change any of them. If you're testing on a project you care about, decide up front what the agent is allowed to change, because shell and file-edit tools are on by default.

Three providers, two errors

My first test against DeepSeek's own API failed with an insufficient balance error. The fix for that is adding credit on the DeepSeek platform. I didn't do that on camera.

Instead I went to settings, chose OpenCode as the provider, pasted my OpenCode key and selected DeepSeek Flash. That failed differently: "error from provider console upstream request model is unavailable". I set the model again and it still failed. I didn't solve that one in the video.

Third try: I created a new OpenRouter API key, named it deepseek, and pasted it in. The test came back with "test". That's the route I used for the rest of the video, first with one of the free models and then with DeepSeek V4 Pro through OpenRouter.

Those are three different situations, and it helps to record them separately: an account with no credit, a model the provider wouldn't serve, and a route that worked. Switching to OpenRouter didn't fix the first two. It went around them.

DeepSeek's model configuration guide explains where these settings live now. The DeepSeek key goes in Settings, then Models, and is stored in $DSH_HOME/.credentials.yaml rather than shown back in the page. Add model provider covers the providers the harness ships with, and a Custom model API option handles any gateway that isn't listed: you give it a provider ID, base URL, API protocol and at least one model. There's also a Fetch available models button that asks the endpoint which models it actually serves. That's the first thing I'd try the next time I see "model is unavailable".

The engine demo and the trajectory view

With OpenRouter working, I pasted a detailed prompt I had written with Claude Desktop, asking for a two-stroke cylinder engine animation as a single HTML file. The harness started building it, and I followed along in the trajectory view, where you can preview each step as it goes. I hadn't seen that in another coding harness. DeepSeek's page describes it as a developer tool for viewing execution trajectories and run details when you need to troubleshoot tool calls.

OpenRouter's logs showed the requests coming from DeepSeek V4 Pro on the DeepSeek harness, and about 3 cents had gone by partway through. It then validated the HTML structure and reported the file finished.

The result was still buggy

I opened the file and it was very buggy. Paused, it looked normal. Playing, it did something strange. I opened it in Chrome as well and saw the same problem. The session used 196,000 tokens, and I estimated the cost at around 18 cents. I asked it to fix the bugs, and at the end of the video it was still buggy.

So the honest summary is: cheap for what it produced, with a genuinely useful trajectory view, but the output didn't work. I said in the video that it was very cost effective compared to Claude Code. That's my impression from this one task, not a side-by-side test on the same prompt.

If you try a similar build, write down what the animation should do before you look at it. When it breaks, describe the exact behaviour ("it looks right while paused but breaks as soon as I press play") instead of "fix the bugs", and keep the broken file so you can compare. For a fair comparison with other tools, use the approach in my guide to choosing a model for a task.

FAQ

Was the final engine demo working?

No. It was buggy in both browsers I tried, and still buggy after I asked the harness to fix it.

Did switching to OpenRouter fix the insufficient balance error?

No. OpenRouter gave me a working route that skipped DeepSeek's own API. To use DeepSeek's API directly you need credit on the DeepSeek platform.

What should I check if I get "model is unavailable"?

Check that the model ID is one the provider actually serves. DeepSeek's model configuration guide includes a Fetch available models option that asks the endpoint for its list. I didn't fix this error in the video. I switched to OpenRouter instead.

Do I have to build DeepSeek Harness from source?

No. The README offers npx @deepseek-ai/dsh web once Node.js is installed. I built from source in the video, which takes longer.
