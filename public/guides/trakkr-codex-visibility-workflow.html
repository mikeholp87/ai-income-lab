Trakkr and Codex: AI Visibility, Crawlers and Visits

Quick answer: Connect Trakkr's hosted MCP server to Codex, pull the action list into a report, and read it before you let Codex edit anything. Keep AI visibility, crawler visits, citations and real visitors as separate numbers. An assistant naming your brand is not a click, and a fix list is not a result.

I use Trakkr to track how my YouTube analytics app, Tube Analytics, shows up in AI answers. In my video I go through the visibility dashboard, the crawler logs, tracked prompts and my referral traffic, then ask Codex to pull the latest Trakkr action items over MCP and implement them.

The most useful lesson was not a ranking blueprint. It was that these screens measure different things. An assistant naming my brand, a crawler fetching a page and a person visiting the site are three separate events, and my own numbers show how far apart they can be.

What I was measuring with Trakkr

When I recorded this in August 2026, the main Trakkr dashboard had Tube Analytics at position 9 out of 209 relevant competitors, with vidIQ and TubeBuddy at the top. On the visibility view, Tube Analytics came out ahead of every competitor, including youtube.com. When I asked ChatGPT "what are the best apps for competitor tracking on YouTube?", it listed Tube Analytics first.

Both things were true at once because they measure different samples. One prompt answered in my favour is a single data point. The dashboard position is an aggregate across many tracked prompts and models. My overall visibility score was around 33, against roughly 87 for vidIQ, so "outranking everyone" only held for some views. When you read your own numbers, write down the prompt set, the models, the date and the answer behind each score.

The prompt view was more useful to me than the headline number. One prompt I opened showed I wasn't ranking for it at all, which tells me I probably need another article that answers it. Trakkr describes visibility on its site as your score across the AI models it tracks, which is narrower than a search-engine rank.

Crawlers, citations and visitors are different numbers

Under Traffic and then Crawlers, Trakkr shows which AI crawlers fetch your pages. On August 5 it logged about 4,300 visits from Claude's crawler and about 7,400 from ChatGPT's. One page alone was being crawled around 288 times a day. Each page also gets a citation-readiness breakdown covering things like schema, crawlability, entity coverage and answer blocks.

Then I opened referral traffic, and the picture changed. For that week ChatGPT sent me about 21 visitors and Claude about 18. Over three months ChatGPT sent about 700 visitors while Google sent about 39,000. Thousands of crawler hits turned into a small number of human visits. I still expect AI search to grow, but crawler activity is not traffic, and traffic is not sales.

Connect Trakkr to Codex

The MCP connection was already set up when I recorded, so the install isn't in the video. Here is the current documented route, checked against Trakkr's and OpenAI's docs on November 11, 2026.

Trakkr runs two MCP servers. The public knowledge server at https://api.trakkr.ai/public/mcp needs no account and only reads Trakkr's public docs and research. The authenticated server at https://api.trakkr.ai/mcp reads your own brands, prompts, citations, competitors and actions. Trakkr says the authenticated server is included on every paid plan and signs you in with OAuth over Streamable HTTP.

Codex reads MCP servers from ~/.codex/config.toml. A Streamable HTTP server needs a url, and you can set an approval mode per server. The writes mode makes Codex ask before any tool that isn't marked read-only, which matters because some Trakkr tools perform actions:

[mcp_servers.trakkr]
url = "https://api.trakkr.ai/mcp"
default_tools_approval_mode = "writes"

Then sign in. OpenAI documents codex mcp login <server-name> for OAuth servers, with --no-browser for a terminal without a local browser:

codex mcp login trakkr

Inside Codex, /mcp lists your active servers. Trakkr suggests a first read that confirms which brands the connection can see:

Use Trakkr's list_brands to show the brands I can access and their IDs.

If the tools don't appear, start a new Codex session. The connection inherits your Trakkr permissions, so it can't see brands your account can't already access.

Pull Trakkr actions into Codex

With Trakkr connected, I asked Codex to get the latest actions. It queried Trakkr for the newest AI crawler findings and action items, then ranked them by crawlability, citation impact and implementation urgency. My site already scored 95 out of 100 in Trakkr, and Codex still found items to fix. I also asked it to pull in Trakkr's ideas, which are suggested prompts and citation gaps worth closing.

On camera I told it to implement the fixes straight away. For a site you care about, I'd split that into two steps. First ask for a written report that lists each page, the condition Trakkr found, the date of the finding and the proposed change. Then give a separate go-ahead once you've read it. The approval mode above makes that split easier to keep.

Treat the fix list as hypotheses

The fixes Codex proposed were an llms.txt update, some sitemap issues and a robots.txt rule that was blocking pages it shouldn't. The robots.txt and sitemap items are ordinary crawlability problems, worth fixing on their own merits.

In the video I called llms.txt "probably the single most important file" for ranking in AI search. I wouldn't say that now. Trakkr's own MCP page lists a research resource called "The llms.txt truth", which it describes as an honest null result on llms.txt. Treat that file as cheap housekeeping, not a ranking lever.

The same caution applies to the article checklist I showed on my blog: key takeaways, an author bio, JSON-LD, internal links, sources and an FAQ. Those are good habits for any article. A page passing a tool's checklist still doesn't prove that it caused more citations, visits or sales.

Check the result with the same prompts

I ended the video while Codex was still working, so I can't show you whether those fixes moved anything. To check your own changes, open the files Codex touched and confirm the change is what you approved and that it actually deployed. Then rerun the same tracked prompts on the same models and compare against the scores you wrote down before. Keep crawler counts, citations and referral visits in separate columns so one never stands in for another.

FAQ

Does more crawler activity mean more traffic or sales?

No. In my case, thousands of AI crawler visits turned into about 21 ChatGPT visitors in a week, while Google sent far more. Track crawl access, citations, referrals and conversions as separate numbers.

Was Tube Analytics really ahead of every competitor?

On some views, yes. ChatGPT listed it first for one prompt, and one visibility view put it ahead of youtube.com. The overall dashboard had it ninth of 209, with a visibility score around 33 against roughly 87 for vidIQ. Which answer is right depends on the prompt set you measure.

How do I connect Trakkr to Codex?

Add a [mcp_servers.trakkr] table with url = "https://api.trakkr.ai/mcp" to ~/.codex/config.toml, run codex mcp login trakkr, then check /mcp in Codex. The authenticated Trakkr server needs a paid plan.

Should I let Codex implement the fixes automatically?

I did on camera, but I recommend a report first and approval second. Set default_tools_approval_mode = "writes" so Codex asks before Trakkr tools that change data, and review the diff before you deploy. For another dashboard-to-agent workflow, see the OpenSEO guide.
