Claude Code tutorial for beginners: install and use it

Quick answer: this Claude Code for beginners walkthrough starts with an account and installation, then takes you through one project explanation and one small change you can inspect.

This is a short Claude Code tutorial for your first session. Claude Code is a coding agent that can read project files, edit code and run commands, according to Anthropic’s official overview. This guide uses the terminal: the text window where you enter commands. The aim is a useful first session, not a finished application.

Watch Mike’s Get Started with Claude Code in 10 Minutes alongside this written checklist. The steps below use current official documentation; they do not assume that every screen still matches the recording. Treat ten minutes as a suggested practice session, with extra time for installation or login trouble.

Claude Code for beginners: prepare one small project

Choose a project you own and can restore from a backup. A simple website or a folder with a README is enough for this exercise. Avoid starting with a client’s production application. Write down one question about the project and one tiny improvement before opening the tool.

A useful finish line is: “I can explain what this folder contains, identify the file I changed, and show that the change matches my request.” Keep that note beside the terminal. If the conversation turns into a redesign, return to the original task.

Minutes 0–2: choose the account and billing path

Anthropic’s pricing page says Claude Code is included in paid plans, including Pro, Max, Team and Enterprise. For an individual, Pro is listed at $20 billed monthly, or $200 billed annually; Max starts at $100 per month. Review the checkout total before buying. An existing Pro subscription is a reasonable place to begin this exercise.

The Pro and Max help article confirms that Claude chat and Claude Code share usage limits. More terminal work can leave less capacity for chat. There is no promised number of projects you can finish with a subscription.

That help article also distinguishes subscription access from separately billed API usage. Use the account holding your subscription. If your machine already has an ANTHROPIC_API_KEY configured, investigate it before continuing: API authentication can result in API charges. If you reach a limit, waiting for a reset is an option; do not accept additional paid usage without understanding it.

Minutes 2–4: install and check the command

Use Anthropic’s native installer. Its setup requirements list macOS 13 or later, Windows 10 version 1809 or later, and supported Linux distributions including Ubuntu 20.04 or later and Debian 10 or later. It also needs 4 GB of RAM or more, an x64 or ARM64 processor, and an internet connection. On native Windows, Git for Windows is optional: with it Claude Code uses Git Bash, without it PowerShell.

For macOS, Linux or WSL, the official installation command is:

curl -fsSL https://claude.ai/install.sh | bash

For Windows PowerShell, use the PowerShell installer:

irm https://claude.ai/install.ps1 | iex

Copy only the command for your terminal. These commands download and execute Anthropic’s installer, so confirm the domain before running them. In WSL, install from the Linux terminal, as the Windows setup instructions explain.

Then run the documented installation check:

claude --version

You should see a version number. If the command is not found, follow the setup page’s troubleshooting link before trying another installer. Get this single check working before moving on.

Minutes 4–6: sign in and understand the folder

Open the terminal in your project folder. The official quickstart starts a session like this; replace the example path with your own:

cd /path/to/your/project
claude

On first use, follow the browser authentication prompts. For subscription access, choose your Claude account. To change accounts later, enter /login inside the session. When sign-in finishes, the terminal shows Login successful; press Enter to continue.

Before requesting changes, check the displayed working directory. Start with this brief:

Explain what this project does and identify its main files.
Read and summarize only; do not edit or run project scripts.
Point out anything you cannot determine from the files.

Read the answer against the files yourself. Can you find the entry point it names? Does the README agree with its description? If an explanation seems vague, ask for a filename and the relevant passage. A convincing summary is a starting point for review.

Understand permission prompts before approving them

Use Shift+Tab to switch permission modes, as described in the quickstart, and select Manual for this exercise. The permissions reference calls this mode default; the name does not mean every new session starts there.

In Manual mode, ordinary project reads need no approval, while file edits and many shell commands ask. Existing permission rules and sandbox settings affect prompts. Auto mode uses a classifier for actions instead of routine human approvals. Choosing “Yes, don’t ask again” lasts until the session ends for file edits, but applies permanently to that repository and command for shell commands.

At a prompt, read the proposed action and its target. For this exercise, approve only work you can connect to the tiny task. If a command is unfamiliar, decline it and ask what it would do. Avoid granting broad ongoing approval just to clear the dialog.

Minutes 6–8: add a short CLAUDE.md

CLAUDE.md holds persistent project instructions. Anthropic documents placing it at the project root and using /init to draft a starting file. Review generated instructions before keeping them. Crucially, these instructions are context, not enforced permissions. Personal rules for every project can go in ~/.claude/CLAUDE.md, and private notes for one project in CLAUDE.local.md. Anthropic suggests keeping each file under 200 lines.

For this practice project, a short handwritten file might say:

# Practice project
Explain the proposed change before editing.
Keep this exercise limited to README.md.
Do not install dependencies, publish, or deploy.
Report the changed text and how it was checked.

Adapt those instructions to the folder you chose. Add a check command only after confirming it actually exists in the project. Do not fill the file with guessed commands or unrelated preferences. Keep permission settings aligned with your intended scope too.

Minutes 8–10: make one change and inspect it

Pick a typo you can already see in the README. Specify the exact sentence and replacement, then ask:

Correct only this README typo: [original] → [replacement].
Leave other wording and files alone.
Show the difference and report what you checked.
Do not commit, push, or deploy.

Inspect the proposed edit before approval. Afterwards, open the file and compare it with the original. If the project uses version control, review the diff in your editor. The success condition is deliberately small: one intended correction, no unrelated edits, and a clear explanation of what changed.

A second safe exercise is to ask for an explanation of one function or a list of unclear README instructions, without requesting edits. Save dependency updates, authentication changes and deployment for a task whose behavior you can test. For a fuller practice loop, use the small-change workflow guide.

Common mistakes that make the first session harder

  • Starting in the wrong folder. Check the path before giving the first prompt; do not use a broad personal folder as your practice project.
  • Asking to “fix everything.” Name one file, one change and a finish condition.
  • Approving unfamiliar commands. Pause and request an explanation in terms you understand.
  • Accepting a completion message as proof. Open the output and compare it with the request.
  • Expanding the task mid-session. Record new ideas separately and finish the original correction first.

You have completed this exercise when you can explain the change without relying on the assistant’s summary. For choosing between tools afterwards, read Claude Code vs Codex.

FAQ

Which plan should a beginner use?

If you already have Pro, start there before buying more capacity; Pro and Max both include Claude Code. The free claude.ai plan does not include Claude Code.

Do I need an API key with Pro or Max?

No. Sign in with the Claude account that holds your subscription. API credentials are a separate billing path, so check which account you are using.

Does Claude Code ask before every action?

No. In Manual mode, ordinary project file reads do not need approval, while edits and many commands do. Existing rules and settings can change which prompts appear.

What belongs in CLAUDE.md?

Put project instructions such as the relevant files, verified check commands, and boundaries for changes in CLAUDE.md. Treat these as guidance, not enforced permissions.

What is a good first task?

Ask for a project explanation, then fix one README typo or clarify one sentence. Compare the result with the original and stop if unrelated files change.
