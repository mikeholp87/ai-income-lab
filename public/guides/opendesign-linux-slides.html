OpenDesign (Open Design) on Linux: Source Setup and Slides

Quick answer

Follow the recorded Linux source setup, make one first design, then export a standalone HTML deck. On Linux that means cloning the official repo, using Node 24 with Corepack, then running pnpm tools-dev run web. Local agents, BYOK keys and hosted credits are billed separately, so a free desktop app is not free inference.

OpenDesign, also written Open Design, is an open-source design workspace that drives whichever coding agent or model you connect to it. I tried it as a free alternative to Claude Design, mainly to make visuals and slide decks for my YouTube videos. In my video I build it from source on Linux, fix two dependency errors, sign in, generate a short animated test and then turn a video topic into an HTML slide deck.

The deck came out well. This guide covers how I got there, the documented setup commands you should use instead of copying my fixes, and what the money side actually looks like.

Choose the setup path you are actually using

On the official site the download only offered macOS and Windows, so on Linux I went to the official GitHub repository, pulled the source and ran it on localhost. That is still the documented route. The site’s FAQ says there is no Linux build on the download page and Linux users can run OpenDesign from source, and the README says the latest official release has no prebuilt Linux artifact.

The repo had about 100,000 stars when I recorded, and the project lists a long set of agents it can use, including Claude Code, OpenCode, Hermes and Antigravity. OpenDesign doesn’t ship its own agent. It uses one already on your machine, a model key you provide, or its hosted cloud.

Run it from source on Linux

These are the commands from the README’s run-from-source section and the repo’s QUICKSTART. The project requires Node 24 (~24) and pins pnpm 10.33.2, which Corepack selects for you:

git clone https://github.com/nexu-io/open-design.git
cd open-design
corepack enable
corepack pnpm --version   # should print 10.33.2
pnpm install
pnpm tools-dev run web

Open the URL that tools-dev prints. The QUICKSTART notes that development ports are allocated dynamically, so don’t assume a fixed port. If you use nvm, it suggests nvm install 24 and nvm use 24 before running pnpm.

Resolve the observed dependency problem

My first attempt failed with a message that a local package.json existed but node_modules was missing, so the dependencies hadn’t been installed. Fixing that led to the next error: Corepack not found. I installed Corepack with Homebrew, which I already had on that machine, approved it, and after that OpenDesign started. I was running all of this inside Herdr, which keeps terminal sessions saved between runs.

That fix worked on my setup. It doesn’t mean you need Homebrew. If you hit the same errors, check your Node version first against the ~24 requirement, then run corepack enable and the version check above. A project reply in the repo’s Linux issue explains that newer Node and pnpm versions are rejected on purpose until they are tested, so a version error is a signal to switch to Node 24, not to force it.

Pick an agent or model before generating

When OpenDesign loaded, I signed in with my Google account, created an OpenDesign account and approved the login. That put me on the hosted route, which showed about 50 cents of credit. From there I could pick a folder, browse sample prompts including motion design, and choose a model such as DeepSeek V4.1 Flash or Claude. There is also a place to add API keys for OpenAI, Anthropic and Google Gemini.

Signing in isn’t required. The official site describes three routes. With a local CLI agent such as Claude Code or Codex, you need no OpenDesign account, but your agent’s own subscription or API usage still applies. With BYOK, you add your own key, your provider bills you and no OpenDesign credits are used. With hosted, you sign in and usage draws on plan credits. The FAQ adds that a BYOK key can generate designs but can’t edit files in your project, so use a local agent if you need that.

For my first test I asked for a 20-second paper cutout story. The plan and balance page showed it consuming credits, 1 cent at that point. In about a minute I had a preview I was genuinely impressed by, and the code behind it was a single HTML file. I could also share it or open it in an editor such as Cursor, VS Code or Antigravity.

Build a deck from checked source material

Then I tried something I’d actually use: a slide deck for a video on getting AI consulting work by setting up an agent in GrokBot to find leads and send email pitches. I gave it my prompt and a YouTube video on the topic as a reference, hoping it could pull the transcript. After three to four minutes I had a complete deck I could scroll through.

It looked like it took a lot of the information from that video and put it into its own design. I didn’t check each slide against the source on camera, though, so do that yourself before presenting. A good-looking deck can still contain claims the source never made.

Export and inspect the independent file

I exported the deck as a standalone HTML file and opened it in its own browser tab, where I could navigate through all the slides. That is the check that matters: the file works outside OpenDesign’s preview.

The site’s FAQ lists standalone HTML, PDF and PNG exports, and decks can also export as editable PowerPoint. I only tried HTML, so I can’t tell you how the others turn out.

Troubleshooting and limits

Keep setup errors and generation errors apart. A failure during pnpm install or startup is about Node, Corepack or dependencies. A failure while generating is more likely the model route: a missing key, a signed-out agent or an empty balance.

On cost, the whole session came to roughly 16 cents of hosted credit by the end. I called it free in the video, but it did use credit, and topping up, auto-recharge and paid plans were all offered. The site says the free tier covers local agents and BYOK, while paid plans add hosted model credits. Check current plans before relying on any figure from my session.

FAQ

Does Linux have the same download as Windows?

No. The official site has no Linux build on its download page, and the README says Linux users run OpenDesign from source with Node 24, Corepack and pnpm tools-dev run web.

Did the reference video become the deck’s content?

It looked that way. The deck reused a lot of information from the video I supplied, but I didn’t compare every slide with the source, so check each claim before you present it.

Is OpenDesign free?

The app is free and open source, and the free tier covers local agents and your own API keys. Your agent or model provider still bills its usage, and the hosted route uses credits. My session used roughly 16 cents of hosted credit.

Do I need an OpenDesign account?

Only for the hosted models. I signed in, but the site says you can start with a local coding agent or your own API key without an account.
