Ghostty Config on Debian: Themes and Reload Checks

Quick answer

Use current distro docs to install Ghostty, put your settings in ~/.config/ghostty/config.ghostty as key = value lines, then reload with Ctrl+Shift+, and open a fresh window to confirm. The memory numbers I saw against Konsole come from one session on my laptop, not a benchmark.

I switched from Konsole to Ghostty on my Debian machine because Konsole had started using a lot of memory while I ran coding agents in it all day. In my video I install Ghostty from the package manager, set up a theme, edit the config file, reload it and run Codex inside the new terminal.

This guide covers what I did on screen and the parts of Ghostty’s official docs you need to repeat it: where the config file lives, the one-line way to set a theme, and how reloading works. A terminal does not change the model behind your agent, so treat this as a comfort and resource choice, not an AI upgrade.

Choose installation instructions for your distribution

I started on ghostty.org, went to Download, chose Linux and the package-manager option, and searched the list for Debian. Then I opened a new tab and ran an apt install for Ghostty. My system was Debian Forky with Linux 7.1.9, and apt reported that the latest version, 1.3.1, was already installed.

That tells you what my machine had available, not what yours has. Ghostty’s official binaries and packages page is clear about this: the project only ships official prebuilt binaries for macOS, and Linux packages are built by distribution maintainers or community members. Ubuntu has Ghostty in its official repository from 26.04, while Debian is listed under community-built .deb packages, and the docs warn that community binaries carry more risk than distro or project builds.

So before you paste an install command from my video, check which source your distribution actually uses. I also mentioned building from source in the video. I didn’t do it, and for Debian or any of the major distros a package is the simpler route.

Know where the Ghostty config lives

In my video I opened the config file from the terminal itself: right-click, Config, then open the config file. That is the easiest way to find the file Ghostty is really loading.

If you prefer to go to it directly, the configuration docs say the file is named config.ghostty (just config before version 1.2.3) and lives under $XDG_CONFIG_HOME/ghostty/. When XDG_CONFIG_HOME isn’t set, that means ~/.config/ghostty/. Configuration is optional, so on a fresh install there may be no file at all and Ghostty simply uses its defaults.

Keep a copy of a working file before you paste in a large block of settings. If something breaks, you can put the old one back instead of hunting through dozens of lines.

Change Ghostty themes and settings one at a time

For my own setup I used a community Ghostty config generator in the browser. Under Colors I picked a dark theme (Nocturnal Winter, as I said on screen) and a light one, previewed them, then used its import and export section to copy all the settings to my clipboard and pasted them into my config. I also changed the cursor colour and cursor text colour, set the window theme to dark, set window state saving to always, adjusted the window subtitle and bumped up the font size so it stays that size.

You don’t need that tool. Ghostty ships with hundreds of built-in themes, and the colour theme docs show the whole thing taking one line. This is the smallest useful setup, taken from those docs:

# List the built-in theme names
ghostty +list-themes

# Then in ~/.config/ghostty/config.ghostty
theme = dark:Catppuccin Frappe,light:Catppuccin Latte

With separate dark and light themes, Ghostty switches automatically with your system appearance. A single theme = Catppuccin Frappe line works too. To see every option with its documentation, the config docs give ghostty +show-config --default --docs, which prints the full default configuration to the terminal, so pipe it into a pager.

One thing I learned while checking the option reference for this guide: window-save-state, which I set to always, is currently macOS only and has no effect on Linux. That is exactly why it is worth looking up each option a generator exports instead of trusting the whole block. Keys are case-sensitive, and the theme docs warn that a theme file can set any option, so read third-party theme files before using them.

Reload and open a fresh terminal when needed

I reloaded through the same right-click menu: Config, then Reload Config. The theme and other changes applied straight away, and I opened a new window from the Ghostty menu to start working.

The config docs list Ctrl+Shift+, as the default reload shortcut on Linux. They also note that some options can’t be reloaded at runtime and others only apply to newly created terminals. Font size is one to watch: the reference says a runtime change only affects terminals where you haven’t already adjusted the size manually. If a change seems to do nothing, open a fresh window before assuming the setting is wrong, then check the option name and the file path.

What I saw on memory use

With Konsole still open and Codex working in it, my system monitor showed Konsole at about 1.7 GB of memory, while Ghostty with almost the same number of tabs was around 270 MB. I also felt it was using less CPU.

That difference was big enough to make me switch, but it was one reading on one laptop, with different things running in each terminal. I didn’t control the workload, so I can’t tell you how much memory you will save. If memory is your reason to switch, compare the two terminals yourself with the same tabs and the same tools running.

Run the agent you already installed

Inside Ghostty I opened Codex and it worked exactly as it did in Konsole. Ghostty doesn’t bundle any agent. Codex was already installed on my machine, along with its own account.

I also showed Hermes Agent, which I already had running, being asked to read the Ghostty docs and suggest improvements to my config. It started fetching the docs and pulling out useful options, but I didn’t apply its suggestions on camera because my config was already done. If you try the same, review each suggested line against the option reference before saving, and keep that agent focused on the config file rather than an unrelated project.

A good final check is boring on purpose: ordinary shell commands work, your agent launches, and the theme still looks right in a brand-new window.

FAQ

Where is the Ghostty config file on Linux?

At ~/.config/ghostty/config.ghostty by default, or under $XDG_CONFIG_HOME/ghostty/ if you set that variable. Versions before 1.2.3 used a file named config. You can also open it from the right-click menu under Config.

How do I reload the Ghostty config?

Press Ctrl+Shift+, on Linux or use Config, then Reload Config from the right-click menu. Some options only apply to new terminals, so open a fresh window if a change doesn’t show.

Will Ghostty save me as much RAM as it saved you?

Not necessarily. I saw about 1.7 GB in Konsole against about 270 MB in Ghostty, but that was one session with different workloads in each terminal. Measure on your own machine with the same tabs open.

Do I need a third-party theme helper?

No. I used one, but Ghostty has built-in themes you can set with a single theme = line, and ghostty +list-themes shows the names.

Does a terminal supply model access?

No. Your agent and provider account stay separate from the terminal. To organise several agents in one terminal, see my Herdr TUI walkthrough.
