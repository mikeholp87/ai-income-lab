Quick answer

Install the current official Herdr desktop app, open one repository as a space, and run agents in separate tabs. Closing the window is not the same as stopping herdr-core. The memory figure I saw in my video is one reading on my machine, not a benchmark.

Herdr is my favorite way to run terminal coding agents, and it now has a desktop app for Linux, Windows and Mac with spaces, tabs and a customizable interface. Think of it as the place you organize agent work. It isn't a model, and it doesn't make a coding task finish correctly.

The important distinction is between the window you see and the process running your agents. According to Herdr's official site, the desktop app uses a separate local service called herdr-core. Closing the app does not stop those processes. Restarting the machine or stopping herdr-core does.

Below I walk through how I set it up, customized it and ran several agents side by side, then cover the limits Herdr documents. Where I quote Herdr's own docs rather than what I did on screen, I say so.

What Herdr does, and what it does not replace

Herdr's official documentation describes a native app that runs coding agents in real terminals. A space can represent a repository, while separate tabs hold separate tasks. An agent that supports the OSC 7501 status protocol can report whether it is working, finished or waiting for help.

An agent without that protocol can still run. What it lacks is the same status reporting. A missing status indicator is therefore not, by itself, proof that an agent failed to start.

The app also allows an agent to change parts of the workspace interface. Herdr documents layouts, tabs, keyboard settings and themes as plain configuration files. This is a different concern from asking an agent to edit your application code. Keep those two scopes separate when you evaluate the tool.

A nicer workspace doesn't make the generated code correct. Keep reviewing proposed changes and checking the project itself. My guide to building apps with AI coding agents covers that small-change review loop.

Before you install

Check three things before starting:

  1. Your platform. Herdr currently lists macOS on Apple silicon, Linux on x86_64 and arm64, and Windows on x86_64. Check the official site for the installer that matches your machine.
  2. Your coding agent. Herdr runs terminal programs. You still need the coding tool you intend to use and whatever account access that tool requires. Do not assume that installing a workspace supplies a model subscription or API allowance.
  3. Your practice project. Choose a small local repository you own and can restore. Avoid production credentials and sensitive client data for the first session.

If Claude Code itself is new to you, read my Claude Code beginner guide first. This one focuses on the Herdr workspace around it rather than repeating the full Claude Code install.

Follow my desktop setup

1. Get the installer from the official site

At 00:36 in my video I open herdr.dev, click download and copy the one-line curl installer for Linux into a terminal. On Windows you use PowerShell instead. Then I search for Herdr in my own application launcher and open the desktop app.

I didn't read the command out on camera, so copy it from the official download page for your operating system rather than from a screenshot. Review any installer before running it. The launcher I use is my own open-source tool. You don't need it for Herdr.

The desktop app and Herdr TUI are separate programs. Herdr's documentation says the desktop app runs on herdr-core, while the original TUI has its own agent server. Installing the desktop app should not be treated as migrating all terminal workspaces.

2. Choose a theme, panels and a space

Around 01:13 and 01:45 I pick dark mode, turn on the offered panels and open Spaces. I was hoping my command-line workspaces would carry over, but they didn't migrate automatically. I just carried on in the new app.

I skipped the remote-machine option because I only use one computer, so I don't cover remote setup here. The panels sit beside the terminals and can be opened or closed later from the tab bar. Keep the layout simple enough to tell terminal output, file changes and agent activity apart.

3. Start Claude Code and resume its own session

Around 02:27 I launch Claude in the desktop terminal and use its resume command to get back to an audit I had been running in the terminal. The session was there, and I carried on working in the GUI.

That worked because of Claude Code, not Herdr. Claude keeps its own session history, so resuming it says nothing about Herdr migrating TUI spaces. Herdr provides the terminal, and the agent brings its own history and login.

In the video I also push straight to main. That's fine on my own project, but don't copy it as a default. Review the diff and run the project's checks, then use your normal branch and approval process. My small-change coding workflow covers that review loop.

4. Try a built-in theme before importing one

At 03:08 I switch to the Windows 98-style theme, complete with Clippy, a Start menu, Minesweeper and Solitaire, then switch back. It's fun, but agents work the same in any theme.

At 04:19 I pick a theme from the gallery and ask an agent to read Herdr's instructions and import it from GitHub. Once it finished, the new theme showed up in settings. I tried it, and it looked good, but I still went back to the default.

I didn't show the full command or the theme's repository URL on screen, so I won't guess them here. Use the official gallery and look at a theme's source before you let an agent change your configuration.

Separately, Herdr documents interface files under ~/.config/herdr-app, including an AGENTS.md explaining configurable settings, layouts and themes. Treat a layout change as a bounded configuration task. It does not need to become permission to rewrite your project.

5. Inspect files and actual changes

Next I open the file browser and the Changes panel. At first nothing showed up, because no agent had edited anything in that folder yet. Once an agent started working in the directory, its changes appeared there. I find that much easier than tracking changes from the command line.

The panel shows what changed, not whether the change is right. Check you're looking at the intended project, read the actual diff and run the relevant checks.

6. Add agents side by side

From 07:12 I open more tabs, and with this theme a new tab starts a coding agent straight away. I run Claude Code, OpenCode, Cursor Agent, Hermes and Codex side by side. They were all already installed and logged in on my machine. Herdr doesn't install or authenticate them for you.

I sent each a quick test and got replies from Codex, Hermes and OpenCode. Hermes took its time to start. Kimi didn't work because I'm not logged in to it, so if a pane sits empty, check that agent's own login before blaming Herdr.

Start with one project and a few clear tasks. Seeing agents side by side is great for visibility, but I didn't test several agents editing the same files at once. Give each one a separate task and review their changes before combining them.

What the memory observation does and does not show

At 09:12 I checked my task manager, and the app was using about 309 megabytes with several agents open. I prefer it to the ChatGPT and Claude desktop apps, which I find CPU-intensive and heavy on memory.

That was one reading, not a benchmark. I didn't total every child process or run a controlled comparison, so I can't promise a fixed figure or a measured saving. Check your own usage while you work, since your agents and projects will differ from mine.

Troubleshooting grounded in the official FAQ

SymptomDocumented explanation or check
An agent runs but is absent from the agent listCheck whether its version supports OSC 7501 status reporting.
Status is missing inside tmuxHerdr says an agent running inside tmux cannot report through it. Its FAQ recommends running the agent in a Herdr pane directly.
Agents from Herdr TUI do not appearThe TUI uses its own server. It does not share agents with the desktop app.
Work continues after the app is closedThe processes run in herdr-core, not in the window. Closing the app is not documented as stopping them.
A pane returns after a reboot but the agent is not workingThe pane can return to a shell in the same folder without the previous program being restarted.

These come from Herdr's FAQ. I didn't hit them myself in the video. If your situation differs, check the current official docs before changing configuration.

Remote machines and performance: boundaries to keep visible

Herdr also documents adding machines reachable over SSH. Their spaces and agents can appear under the machine name in the sidebar. This does not mean the local app moves the underlying work onto your laptop. The remote processes run on the remote machine.

Remote access introduces a separate permissions and credential boundary. Remote installation and access control are outside this local desktop walkthrough.

I didn't set up a remote machine in my video, and the 309-megabyte reading above says nothing about SSH workloads, other machines or a larger set of agents.

Takeaways

I'm going to be using the Herdr desktop app a lot more. It's an easier way to organize terminal coding agents than the command line, with repository spaces, task tabs, status for compatible agents and workspace files you can configure.

The key questions are practical: can you identify the active task, understand whether it needs attention and review what it changed? Keep model access, project permissions and result verification separate from the desktop interface.

FAQ

Is Herdr a coding model?

No. The official site describes an app for running coding agents in terminals. The agent and its model access remain separate concerns.

Does every agent show a working or waiting status?

No. Herdr says status reporting requires OSC 7501 support. Agents without it can still run without that status integration.

Will my agents stop when I close the desktop app?

According to Herdr, closing or updating the app leaves agents running in herdr-core. A reboot or a stopped core service stops the programs. The documented behavior is not automatic task resumption after a reboot.

Does the desktop app share agents with Herdr TUI?

No. Herdr describes them as separate programs with separate agent servers. When I opened the desktop app, my terminal workspaces weren't there. I reopened Claude and used its own resume command to get back to my session.

How much memory does the desktop app use?

On my machine it was about 309 megabytes with several agents open. That's one reading, not a benchmark, and it will vary with your agents and projects. Check your own task manager while you work.
