Quick answer

I built a Windows and Linux task manager in Claude Code in about three hours by asking a chat model for a detailed build prompt, then checking the numbers against another system monitor. Start with a small brief, verify each metric against a tool you trust, and only package the app once the values hold up. The source is on GitHub if you would rather build my version than prompt your own.

I built this while playing a video game. A task manager turned out to be a good coding-agent project, because every number it shows can be compared with what the operating system already reports. A nice CPU graph is not enough. The app has to attach the right process, unit and time window to each value, and you can check that.

In my video I show the finished app running on Linux, explain how I prompted it, and start building installable Linux packages. This guide covers the same ground and adds the official install and build commands, so you can try it yourself instead of only watching.

Start with a small, verifiable brief

My first message was short. I told a chat model I wanted my own task manager that monitors processes and tracks CPU and memory usage, following best practices for Codex and Claude Code, and asked it for a detailed prompt. It came back with a long, complete prompt, and that prompt built the first minimal version of the app in Claude Code. I didn't put the full generated prompt on screen, so I won't pretend to reproduce it here.

If you do this yourself, make the brief checkable. Name the operating system, the values you want on screen and a simple test for each. A process list should show an app appearing when you open it and disappearing when you close it. A CPU figure should roughly track what your existing monitor shows over the same few seconds.

Keep platform gaps visible. I added benchmark tools after the first version, but when I recorded they only worked on Windows. Linux didn't have them yet. Ask the agent to say that in the interface instead of hiding the difference behind identical screens.

Inspect the application by function

The app has an overview, a processes tab, a performance view and a system information page. In the processes tab I can open any process and see its own memory and CPU usage. Performance graphs CPU, memory, disk and network over time, and you can pause it. System information lists the operating system, processor, graphics card and the temperature of each CPU core.

I checked the overview numbers against another system monitor, made by the developer who wrote the original Windows Task Manager. Downloading that tool is what gave me the idea. I wrote mine from scratch rather than reverse engineering anything. My comparison was a side-by-side check on my own machine, not a formal test, so run your own before you trust the numbers.

When two monitors disagree, check definitions before calling it a bug. CPU percentages change with the sampling interval, and memory labels can mean used, committed or cached memory. Ask the agent where each metric comes from. If a sensor is unavailable, the app should say so instead of filling the space with a plausible placeholder.

Separate development from packaging

At the end of the video I asked Claude Code to build Debian and AppImage packages, so the app installs like a normal program instead of running in dev mode. I started that build on camera. I didn't test the finished installers on a clean machine in the video.

The project now lives on GitHub as Tasky, and the old task-manager URL redirects there. The README describes a Tauri 2, Rust and React app. Windows 11 is the primary platform, mainstream Linux distributions are supported, and macOS is not supported yet. On Linux the build produces .deb, .rpm and AppImage bundles, and the README says to build each platform on that platform.

Before you share a package, install it, launch it, check what it asks permission for and uninstall it on the system you're targeting. Keep packaging requests separate from anything that changes startup entries or system services.

Install Claude Code and build it yourself

To try your own version, install Claude Code with the native installer from the official setup docs. On macOS, Linux or WSL the documented command is:

curl -fsSL https://claude.ai/install.sh | bash

In Windows PowerShell the docs give irm https://claude.ai/install.ps1 | iex instead. Then confirm it works. claude --version prints a version number, and claude doctor runs read-only installation and settings checks without starting a session:

claude --version
claude doctor

Claude Code needs a paid Claude plan or a Console account. The docs say the free claude.ai plan doesn't include it. I was on the $20 a month plan for this build and didn't use many credits.

If you'd rather start from my code, the Tasky README lists the steps. It needs Node.js 20 or later and stable Rust. On Debian or Ubuntu it asks for these system libraries first:

sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev

Then run it in development, or build the installers:

npm install
npm run tauri dev
npm run tauri build

The finished bundles land in src-tauri/target/release/bundle/. That is also the point to ask Claude Code for changes: you have a working baseline, and you can see exactly what each prompt alters.

Troubleshooting and boundaries

If a graph looks wrong, check units and the refresh interval before redesigning it. If one platform lacks a feature, document the gap. If packaging fails, paste the exact error and your environment into the next prompt rather than asking the agent to “fix everything.”

Three hours was my time, with Claude Code already set up and a clear idea of what I wanted. The app is still a work in progress, and I'm not claiming it beats established monitors. The closed-source tool I compared against is very good, and I recommend it. Mine is the free, open-source option where you can read and change every line.

FAQ

Can I see the full prompt you used?

I didn't show the full generated prompt in the video. I got it by asking a chat model for a detailed task-manager prompt that follows Codex and Claude Code best practices, and you can do the same. The code on GitHub is now more useful than that prompt, because the app has changed a lot since the first version.

Do I need a paid Claude plan?

Yes, for Claude Code itself. The official setup docs say it needs a Pro, Max, Ultra, Team, Enterprise or Console account, and the free claude.ai plan doesn't include it. I built this on the $20 a month plan. The task manager I built is free and open source.

Does it run on macOS?

Not yet. The README lists Windows 11 as the primary platform and mainstream Linux distributions as supported. macOS has a slot in the architecture but isn't supported.

Does this replace learning how system metrics work?

No. You need enough understanding to tell a meaningful measurement from an attractive chart, especially when two monitors show different numbers for the same thing.
