REA Coding-Agent Case: A Video-Editor Prototype

Quick answer: I connected REA to my coding agents with its one-line npx setup command, then asked Claude Code to rebuild Kdenlive, my usual video editor. After hours of work it produced a prototype called Cutline. Importing, timeline dragging and splitting worked, but playback was glitchy, effects didn't work and pane resizing was broken.

REA stands for Reverse Engineer Anything. The pitch is that you hand an AI agent a piece of software and ask how it works, and REA gives the agent tools to inspect the program and trace its features, even without source code. I recorded this on October 14, 2026, while the GitHub repo was taking off, and I wanted to try the most ambitious version I could think of: rebuild my own video editor.

What REA is

REA's site describes a deliberately narrow loop. Ask about one feature, let the agent inspect the program while it runs, then have it explain or rebuild that feature. The worked example on the homepage figures out why a calculator returns 220 for 200 + 10%. It works with coding agents such as Claude Code, Codex and Cursor, and the project on GitHub is MIT licensed.

I ignored the narrow loop and asked for a whole application. That makes for a fun video, but if you want to judge whether REA is useful for your work, the single-feature question is the better test.

Set it up

REA's setup guide asks for Node.js 22 (22.23.4 or later), 24 (24.22.1 or later) or 26 (26.12.1 or later). Check your version first, then run the setup:

node -v
npx rea-agents@latest setup

The site says to approve the setup plan, then restart your agent. In the video I already had REA installed, so the setup screen just let me choose which harnesses to connect. I picked Claude Code, Codex, Cursor, OpenCode, Grok Build, Hermes and a few others, pressed Enter to apply, and restarted.

Two details from the setup guide that I'd have found useful. If your Linux distribution's own Node.js package is older than the minimum, the guide shows how to install Node 24 with fnm. And there's a prompt version of the setup you can paste into your agent, which asks it to show you the setup plan for approval before it installs anything. I like that because you see what will change first.

The build

I used Claude Code with Sonnet 5.5 on high effort, on the $20 a month Claude Pro plan. My instruction was to use the Reverse Engineer Anything skill to create my own version of Kdenlive, the editor I showed at the start of the video. It took a very long time. My estimate is at least four or five hours.

I didn't keep a written spec or a step-by-step log of that build, so I can't show you exactly what REA inspected along the way or which parts came from inspection rather than Claude's general knowledge of video editors. What I can show is the result.

Testing the prototype

The app looked a lot like Kdenlive. The menus opened, the About box worked, and the View menu toggled panels on and off. One bar from the top right of Kdenlive was missing. Creating a new project made its own folder called cutline, which seems to be the name it gave the app. I set 1080p at 30 frames per second, and the timeline appeared in the bottom right.

Then the real test. I imported a video from my videos folder and dragged it onto the timeline, and that worked first time. I split the clip, zoomed the timeline in and out, dragged clips around and used the spacebar to play.

And the problems. Playback showed a bug as soon as I pressed play. The effects panel didn't appear to do anything yet. Making the preview larger by dragging the pane edge was broken. Those failures matter as much as the parts that worked, which is why they stay in this guide. I didn't test exporting a finished video at all, so I can't tell you whether Cutline can produce one.

Asking for fixes

I told Claude to fix the bugs in the application, "such as the sliders to drag." As I admitted on camera, not the best prompt. The video ends before those fixes landed, so I can't tell you they worked.

If I were doing it again, I'd write one fix request per failure: what I did, what should happen, what actually happened, and the smallest way to reproduce it. For example: "Drag the divider above the preview upward. The preview should grow. Instead the layout breaks." Then I'd retest that exact action after the change, rather than trusting the agent's summary that it's fixed.

Rights before you ship anything

Kdenlive is a free and open-source editor from KDE, which is part of why I picked it. Even so, an inspection tool being able to read software doesn't decide what you're allowed to copy, redistribute or brand as your own. If you plan to publish something built this way, read the original project's licence and check any assets first. I'm not giving legal advice here, and I haven't published Cutline.

The same caution applies to quality. A menu that looks like Kdenlive's isn't evidence of a working render pipeline or format support. For more on scoping builds like this so they're testable, see my guide to building apps with AI coding agents.

FAQ

Did the prototype replace Kdenlive?

No. Cutline handled importing media, dragging clips to the timeline and splitting, but playback had a bug, effects didn't work and resizing the preview pane was broken. I didn't test export.

What does REA need before setup?

REA's setup guide asks for Node.js 22.23.4 or later, 24.22.1 or later, or 26.12.1 or later, plus a coding agent such as Claude Code, Codex or Cursor. Then run npx rea-agents@latest setup, approve the plan and restart your agent.

What should I try first with REA?

One feature in a program you're allowed to inspect, with a small result you can check, rather than a whole application. That matches the loop REA's own site describes.
