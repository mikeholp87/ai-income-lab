Meta Muse Code Setup: API Failure and a Working CLI

Quick answer: I tried to run Muse Wonder inside OpenCode with a Meta Model API key and kept getting an invalid API key error. Installing Meta's own Muse Code CLI and signing in through the browser worked within a couple of minutes. I started a project audit on camera, but the video ends before it finished.

Meta announced Muse Wonder on October 12, 2026, and I recorded this test the next day. I wanted to answer one practical question: how quickly can I get the new model answering inside a coding agent? I left my wrong turns in the video, and I've left them in here too, because the wrong turn is the part most people will hit.

What Meta says Muse Wonder is

Meta's announcement introduces two models, Muse Wonder and Muse Wonder Full. I say "Wonderful" a few times in the video, but the official name is Wonder Full. The announcement says Muse Wonder is available through the Meta Model API and Muse Code, and that Muse Wonder Full is available to Muse Code subscribers.

I walked through Meta's benchmark charts and demos on camera, including the little kitchen game and the calendar and map examples. Those are Meta's own numbers and Meta's own demos. I didn't run a benchmark myself, so treat them as a reason to try the model, not proof it will beat what you already use.

The OpenCode route that failed

My first plan was to skip Meta's tool entirely. I opened the Meta developer portal, got an API key and tried Muse Wonder in OpenCode. Every simple test came back with an invalid API key error.

After going around in circles, I asked Claude Code (Opus 5.5) to find the problem. While it worked, the Meta dashboard started showing input and output tokens, with total spend under one cent. So requests were reaching Meta, but I still couldn't get Muse Wonder to answer inside OpenCode by the time I gave up on that route.

Two lessons from that. First, tokens on a dashboard are not the same as a working setup. The only proof is an answer in the tool you actually want to use. Second, an invalid key error points at authentication or configuration before anything else. Check which key the tool is reading and which provider entry it's attached to before you assume a billing problem, and never paste the key itself into a shared debugging note.

Install Muse Code the documented way

Meta's own CLI was the route that worked. In the video the installer downloaded Muse Code 1.4.7. Meta's Muse Code docs give this one-line installer for macOS and Linux, then a version check, then starting it inside a project. Windows has a PowerShell one-liner on the same page.

curl -fsSL https://dev.meta.ai/install.sh | sh
muse --version
cd /path/to/your/project
muse

On first launch Muse Code asks whether to trust the workspace, then whether to sign in with a browser or an API key. The docs explain that trusting a workspace loads its skills, rules and hooks, so only trust a folder you know. I chose browser sign-in. Honestly, I should have done that from the start. It would have saved me the whole OpenCode detour.

If you skip or close the sign-in screen, the docs say /login reopens it from an interactive session. For CI and other non-interactive use they document a META_API_KEY environment variable and a headless muse exec "<prompt>" mode instead.

Switch the model and send a small test

My session opened on Muse Spark 1.3, not Muse Wonder. Meta's docs currently name muse-spark-1.2 as the default, which tells you the default moves, so check it rather than assume. I typed /model and picked Muse Wonder.

I tried voice input first and it told me voice was not enabled. So I typed "What can you do?" It answered that it could read and explain code, find and fix bugs, add features, write tests and run builds, and it suggested example tasks like fixing a failing test. That exchange cost a fraction of a cent on the dashboard.

That is all a smoke test proves: sign-in, model selection and billing are connected. It says nothing about code quality yet.

The audit I didn't finish

Next I moved into one of my real projects, Tube Analytics, launched muse and asked it to "run an audit and suggest fixes." It started inventorying repo health, running the project's checks, scanning for security and correctness issues, looking for hotspots and running the tests. Spend had reached roughly a dollar when I wrapped up the video.

I didn't show the finished audit, so I can't tell you what it found or whether its fixes were right. If you repeat this, ask for a read-only report first, ask it to name the exact files behind anything important, and only then let it change code.

Which plan gets you which model

In the video I mentioned plans running from about $5 to $200 a month. When I rechecked Meta's Muse Code page on November 11, 2026, there were four: Everyday Usage at $5 a month (includes Muse Wonder), High Usage at $15, Power Usage at $50 (adds Muse Wonder Full) and Maximum Usage at $200 (80 times the Everyday usage). So if Wonder Full is the model you want, the cheapest plan won't include it. Prices change, so check that page before you subscribe.

If you're deciding whether Muse Wonder belongs in your stack at all, don't decide from launch charts. Pick one small task you can judge yourself, the way I describe in my guide to choosing a model for a task, and run it in Muse Code next to the agent you already use.

FAQ

Did you get Muse Wonder working in OpenCode?

No. After Claude Code worked on the problem, Meta's dashboard showed tokens being used, but I never got a Muse Wonder answer inside OpenCode in this video. I switched to Muse Code with browser sign-in, which worked straight away.

Which Muse Code plan includes Muse Wonder Full?

When I checked Meta's Muse Code page on November 11, 2026, the $5 Everyday Usage plan included Muse Wonder, and Muse Wonder Full started at the $50 Power Usage plan. Check the page before subscribing because pricing can change.

Did the audit finish?

Not on camera. It was still working through repo health, checks, security scans and tests when the video ended, with roughly a dollar spent. I can't tell you what it found.

Are launch benchmarks enough to choose a model?

No. They're the vendor's numbers. Use my task-based model evaluation guide to set up a small test you can judge yourself.
