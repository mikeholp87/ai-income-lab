Quick answer

On 18 April 2026 I used Claude Code routines in the web UI and the CLI. Pro included five daily runs. I already had a daily email-triage routine. I added a GitHub event routine that reviews PRs for security issues, a 9:00 a.m. calendar list after Google Calendar connected, and an 8:00 a.m. Bangkok speed audit of tubeanalytics.net that was analysis only. CLI create hit a 401 until I ran Claude auth login. The speed audit found every page returning 403 because curl bots were blocked. A weekly blog-strategy routine was still running at the end. Weekly usage was already at 90 percent, so I stopped the speed-test run. TubeAnalytics is my own product.

Claude Code routines, also called Claude routines, run a saved prompt on a schedule, an event, or an API call. TubeAnalytics is my own product. The product URL from the description is claude.ai/code/routines/. I also said claude.ai/clauderoutines. Five daily runs were the Pro figure on 18 April 2026. I preferred the web UI over the CLI for creating routines because the CLI burned tokens. A later Hermes cron pass is Hermes Agent CLI cron jobs.

1. What Claude Code routines are

I said Anthropic had published this about 14 April, four days before the video. You give a name, a prompt, and either a schedule, an event, or an API call. Examples named were backlog, PR review, and event or API. I already had daily email triage: review unread, categorize, summarize, and draft. Yesterday's review was on screen.

2. GitHub PR security reviews

I created a GitHub event routine on a private repo. The prompt I pasted was:

review this PR for security issues.

The GitHub app was already in the Claude Code terminal. Creating a long-lived token with the Claude subscription still returned failed to access repository, even though I said it already had access. I triggered on matching events and every PR, set permissions, created the routine, and ran it manually. The result covered all four open PRs with overall medium concern, needs verification before merging.

3. Calendar at 9:00 a.m.

A new cron routine at 10:00 a.m. could not use YouTube comments. Connectors were only Google Calendar or Google Drive. I connected Calendar and asked:

give me a list of upcoming events on my calendar.

I later set that to 9:00 a.m. daily as Calendar update.

4. CLI speed audit and a weekly strategy job

In the CLI I opened /schedule. An example was schedule daily PR review at 9:00 a.m. I said create routine, answered "Just analyze the speed" and "Just analyze, no changes," gave tubeanalytics.net, and set 8:00 a.m. Bangkok. A 401 said auth is failing on remote trigger API, likely a session token expired. I ran Claude auth login, authorized in the browser, and continued. The stored prompt was a performance analysis agent for the TubeAnalytics website, daily speed and performance audit, no file changes and no commits. Run now did live TTFB and header checks. All pages returned 403 because the site blocked curl bot requests. It continued with code analysis. I started a weekly Monday blog-strategy routine that commits blog content strategy.md, then stopped the speed-test run at 90 percent credit usage. The weekly job was still running when the video ended.

For scheduled Hermes reports for a site on Vercel, see the Hermes cron jobs with Vercel reports.

What I didn't cover

  • A passing speed audit. tubeanalytics.net returned 403 to curl.
  • Whether the weekly blog-strategy file was committed. The run had not finished.
