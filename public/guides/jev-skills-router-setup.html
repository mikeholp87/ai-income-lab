Jev AI with Coding Agents: Skills, Access and Routed Tests

Quick answer: Jev is TypeSafe's model for fast, structured decisions, not a chat model for your coding agent. I installed the TypeSafe skill, hit a browser-skill failure that turned out to be a missing API key, then ran Codex through a community router. Confirm real requests in the TypeSafe console before trusting any setup.

I recorded this on September 21, 2026, about six days after TypeSafe published Jev. Diego Almeida's launch post was everywhere, with claims of 20 to 200 times faster and 40 to 400 times cheaper than traditional LLMs. Those are TypeSafe's claims, not something I measured. What I wanted was to get Jev connected to Claude Code and Codex and see a real request land in my account.

What Jev actually is

The simplest way I can put it: an LLM is the brain doing the thinking, and Jev is the reflex system making quick decisions. You give it some information and a structured question, and it returns a structured answer with probabilities and confidence scores. It doesn't write text.

TypeSafe's own docs are blunt about this, and it's worth reading before you install anything. Their Jev with coding agents page says Jev is not a drop-in replacement for the LLM behind Claude Code, Codex, Cursor or OpenCode, and that there's no model setting that turns your coding agent into a Jev agent. You keep using your coding agent as normal, and have it write code that calls Jev for decisions like routing, scoring or true/false checks.

Before setting anything up, I also tried a free checker from the Made with Jev collection that looks for "AI slop" tells on a web page. It rated my site 50% and listed what it found, such as gradient headline text. That's a fun demo of the decision style, not a quality verdict.

Access was through a waitlist when I recorded. I was already in through my Gmail account, so I created an account, agreed to the terms, filled in my details and landed in the TypeSafe console. The console gives you a prompt to paste into your coding agent to install the skill, and the API key you'll need later.

Install the TypeSafe agent skill

In the video I pasted the console prompt into Claude Code, mentioned the claude plugin marketplace command, and said I'd already done the same for Codex. I'm not reproducing package names from what I said out loud, because TypeSafe's agent skill page lists the exact commands. For Claude Code:

claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai

For other agents, including Codex, the same page gives npx skills add typesafe-ai/skills --skill typesafe-ai, after which you pick your agent. It installs per project by default, and -g installs globally. Use one method so you don't end up with duplicate copies. After an update, restart Claude Code or run /reload-plugins, which is what I did on camera.

Once it loaded, two TypeSafe skills showed up in Claude Code: a review skill and the main skill for building with TypeSafe. If an agent ignores the skill, the docs suggest naming it in your prompt ("use the TypeSafe skill") or, in Claude Code, invoking /typesafe:typesafe-ai directly.

The missing API key failure

Next I installed a Jev browser-use skill with a one-line command, so Codex could work in my Chrome browser in a similar way to computer use. My first test failed: it couldn't load the Jev configuration. The reason was simple. I hadn't given it my API key yet.

That's the failure worth remembering. A skill showing up in a menu is not the same as an authenticated request reaching TypeSafe. TypeSafe's docs use a TYPESAFE_API_KEY environment variable in their example prompts, with the key created on the console's keys page. Check which variable or config file each tool actually reads, and keep the key out of chat logs, screenshots and committed files.

The router, and checking real usage

Then I installed a package called jev-router with npm, set my Jev API key, and launched Codex through it with its jev codex command. The idea is that it routes each turn to the cheapest suitable model based on Jev's calibration. In my test it routed the turn to GPT 5.6 Soul and replied "Jev test received successfully." The browser-use skill then opened a separate tab and ran its own lightweight Jev test.

One thing I didn't make clear in the video: jev-router isn't from TypeSafe. When I checked its npm listing on November 11, 2026, it pointed to an individual developer's GitHub repo, and TypeSafe's docs don't mention it. It may be perfectly fine, but review a community package like any other before you hand it an API key. That's also why I haven't printed an install command for it here.

I wasn't seeing any spend in the TypeSafe console at first, so I went back and checked. Requests did show up: 4,200 tokens across three requests, for a total that was a tiny fraction of a dollar. That console check is the step I'd never skip. A cheap total still doesn't tell you whether the routing decision was the right one for your task.

My SEO orchestrator run

The last part of the video used an SEO and GEO orchestrator I had already built with Jev for Tube Analytics. It checks a page's SEO elements in parallel, and I had Claude Code, with the TypeSafe skill loaded, optimise it further. Both orchestrators ran end to end on the real API.

The audit bundle reported four of four audits clean, with content SEO, AI discovery and freshness all at 100%. The GEO citation report flagged a comparison citation gap as the top priority, with a confidence score I said could be better: ChatGPT and Claude both failed to cite Tube Analytics on comparison-intent prompts. I told Claude Code to continue fixing issues, and the video ends there.

Keep that in proportion. It's my own tool, and "clean" means the checks I wrote passed. It doesn't mean the site ranks or gets cited. If you want a fair read on Jev for your own work, pick one small decision with known correct answers and compare results, the way I describe in my guide to choosing a model for a task.

FAQ

Can Jev replace the model in Claude Code or Codex?

No. TypeSafe's docs say Jev isn't a drop-in replacement for a coding agent's LLM. Keep your coding agent and call Jev from your code for structured decisions. Even the router I used still sent my turn to an LLM. It used Jev to pick which one.

Why did the Jev browser-use test fail to load its configuration?

Because I hadn't added my API key yet. Once the key was set, requests started appearing in the TypeSafe console.

Is jev-router an official TypeSafe tool?

Not as far as I can tell. When I checked on November 11, 2026, its npm listing pointed to an individual developer's repo and TypeSafe's docs didn't cover it. Review it before giving it a key.

How do I confirm Jev is really being used?

Check usage in the TypeSafe console after a test. Mine showed nothing at first, then 4,200 tokens across three requests.
