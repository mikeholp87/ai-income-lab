# Site audit — November 5, 2026

What this repo does: AI Automation Station publishes videos, guides, project links, and a paid-community funnel. Public APIs handle newsletter subscriptions, enquiries, feed updates, and conversion records. This review assumes a public creator site with modest concurrent traffic, not a high-volume application.

Production reviewed: commit `353e2de`. Source inspection also saw existing uncommitted changes; those are not assumed to be deployed. No application code was changed by this audit.

## Must fix

1. **An old newsletter confirmation can reverse a later unsubscribe.**
   - What this is: confirmation links contain a signed token valid for 48 hours (`api/subscribe.js:101–126`).
   - Problem: a still-valid old link reaches a branch that explicitly sets an unsubscribed contact to subscribed (`api/subscribe.js:141–148`). A reader can unsubscribe and then accidentally resubscribe by opening that old confirmation link.
   - Fix: consume confirmation tokens once, or reject tokens issued before the latest unsubscribe. Require a newly initiated confirmation to resubscribe.
   - If skipped: the subscriber's later choice can be reversed. This is a source-confirmed consent-integrity issue; no production subscriber was used to reproduce it.

## Should fix

2. **Finish the six recently added guides before expanding the library.**
   - What this is: 6 of 41 guides use a smaller page template: `ai-agent-workflow`, `ai-content-creation-workflows`, `build-apps-with-ai-coding-agents`, `chatgpt-linux`, `choosing-ai-models-for-a-task`, and `youtube-channel-growth-workflow`.
   - Problem: all six lack Open Graph images, Twitter title metadata, contents navigation, and the standard FAQ section. Their descriptions differ across metadata, and they have only 1–3 cross-guide links. These are live gaps, not 404s. Missing FAQs alone are not an SEO violation.
   - Fix: use the established guide template, create the missing share/card assets, align metadata, and add a concrete worked example and relevant next steps. Only add FAQs that answer real questions.
   - If skipped: new pages have weaker sharing previews and a less complete reader journey than the existing 35 guides. Existing guide quality tests have already flagged these template differences earlier in this session; they were not rerun in this audit.

3. **Validate the starter kit in Make before treating it as a proven build.**
   - What this is: `public/downloads/make-approved-requests/README.md:24–27` explicitly says the blueprint has not been imported or run in a live Make account.
   - Problem: ZIP delivery and JSON structure do not establish that module configuration, field mappings, and polling behavior work in Make.
   - Fix: import into a new test scenario, connect a fictional Google Sheet, and run the included five behavioral checks. Repair the blueprint if needed and record the verified date/module version.
   - If skipped: a new visitor may receive a downloadable workflow that needs undocumented repair. The current warning is honest and should remain until validation passes.

4. **Measure starter-kit downloads.**
   - What this is: the guide offers ZIP and individual downloads, but `src/reading.js:39–60` has custom click handlers only for YouTube and Skool.
   - Problem: there is no explicit starter-kit download event in repository tracking code. Clarity recordings do not supply a reliable aggregate download-to-signup funnel. GA enhanced measurement might provide generic downloads if enabled externally; that setting was not inspected.
   - Fix: add a consent-aware `starter_kit_download` event carrying kit version, file, and page. Compare downloads with confirmed newsletter signups rather than form submissions alone.
   - If skipped: the value of the new kit cannot be measured clearly.

5. **Prevent duplicate newsletter side effects during concurrent confirmations.**
   - What this is: `api/subscribe.js:141–176` looks up a contact, writes it, then sends owner/welcome emails.
   - Problem: two overlapping confirmations can both pass the initial lookup before either creates the contact. The code has no atomic confirmation-consumption decision or email idempotency key. Whether this duplicates emails depends on provider behavior.
   - Fix: use one atomic token-consumption result to authorize the subscription transition and notification sends; use provider idempotency where supported.
   - If skipped: users and the owner can receive duplicate notifications. This is a source-supported race needing isolated provider validation, not a demonstrated production incident.

6. **Make the free first build easier to find from the homepage.**
   - What this is: the kit is linked from the Make guide and Start here. The live homepage emphasizes membership and watching a video; it has no direct starter-kit link.
   - Problem: a visitor seeking a small hands-on exercise must discover it through other pages.
   - Fix: add one contextual link near the existing free-build action or written-guides section: “Download the free Make.com starter kit.” Measure it using finding 4 before rearranging more of the page.
   - If skipped: fewer visitors may encounter the kit. This is a conversion hypothesis, not a measured uplift claim.

## Nice to have

7. **Add one evidence-rich build case study.**
   - What this is: the homepage shows products, member numbers, projects, and plans, but the inspected page does not demonstrate a member's completed result with evidence.
   - Problem: readers can see the offer without seeing a complete before/after example of what the training helped someone accomplish.
   - Fix: publish one permitted example with the original problem, screenshots, tool costs, failures, and a measured result. Use an owner-built project if no member has approved publication.
   - If skipped: the sales page continues to rely mainly on descriptions and counts. Conversion benefit remains a hypothesis to measure.

8. **Choose one Clarity installation method.**
   - What this is: the uncommitted `package.json:21` adds `@microsoft/clarity`, while source uses the manual script loader in `src/tracking.js:27–39`. No SDK import was found in src, api, scripts, or README.
   - Problem: the additional package currently has no caller and could later lead to a second initialization path.
   - Fix: retain the existing manual loader and remove the unused dependency if it is not part of planned work. This applies to the local workspace only; it is not a deployed dependency defect.
   - If skipped: one unused dependency remains to maintain. Do not initialize both approaches.

## Recommended order

Fix confirmation reuse first. Then complete the six guides and validate the starter kit. Add download measurement and a homepage link together; evaluate traffic before creating more content. Resolve notification concurrency before a larger newsletter campaign.

Verdict: public delivery, sampled mobile layout, search, and consented Clarity collection work. The largest concrete gaps are newsletter confirmation behavior and incomplete guide/kit validation.

Lean: 1 unused dependency can be removed from the current workspace. No line-count reduction is estimated.

Not checked: paid checkout completion, real contact/subscription submissions, real webhook delivery, every video page, external destination links, authenticated Clarity/GA/Search Console dashboards, field traffic distributions, dependency advisories, production credentials, full keyboard/screen-reader/contrast compliance, or penetration testing. No application test/build code was executed during this audit because the security workflow's required isolated execution environment was not established. Security review was source-only; normal public page browsing was used for UX and delivery checks. Findings about provider races require validation. No code changes or deployment were performed.
